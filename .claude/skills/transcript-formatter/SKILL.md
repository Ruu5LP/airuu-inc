# 文字起こし整形スキル

生の文字起こし（フィラーだらけ、改行なし、話し言葉のまま）を読める記録に整えて、
このリポジトリの `projects/` 配下に残し、要点をDiscordに送る。

## 手順

1. **文字起こしを整形する**
   - フィラー（えーと、あの、みたいな）や言い淀み、重複を除く。
   - 意味のまとまりで改行・箇条書きにする。**内容は変えない**（言ってないことを足さない、要約で断定を強めない）。
   - 末尾に3〜5行の要約をつける（決定事項・次のアクションがあれば明記）。

2. **どのプロジェクトの話か判断する**
   - [[プロジェクト]]（`projects/projects.md`）の一覧と、各プロジェクトの `index.md` / `log.md` を見て、
     内容が一番近いものを選ぶ。
   - 迷ったら、選択肢を2〜3個示してRuuに確認する（新しいプロジェクトを勝手に作らない）。
     どのプロジェクトにも属さない雑多な内容なら、無理に押し込めず「今回はどこに置く?」と聞く。

3. **該当プロジェクトの log.md に追記する**
   - 既存の `log.md` があれば、そのフォーマット（見出しの粒度、書き方セクションのルール）に合わせて
     新しいエントリを**上に**追記する。
   - `log.md` がまだないプロジェクトなら、`projects/sns-marketing/log.md` の形式
     （frontmatter: title/tags/aliases、「書き方」セクション、新しいものを上に追記）に寄せて新規作成する。
   - 元の文字起こし全文は `<details><summary>元の文字起こし</summary>...</details>` で折りたたむ。
     長い場合は別ノートに分けて wikilink で繋ぐ。

4. **要点をDiscordに送る**（Webhook URLが設定されている場合のみ）
   ```bash
   .claude/skills/transcript-formatter/send_discord.sh "3〜5行の要約テキスト"
   ```
   - `DISCORD_WEBHOOK_URL` が未設定ならスクリプトがその旨を表示して終わる。黙って諦めず、
     Ruuに「Webhook未設定だから送信スキップした」と伝える。

## Webhook URLの置き場所（重要: リポジトリにベタ書き・コミットしない）

- **ローカルのClaude Code CLI**：リポジトリ直下に `.env` を作り `DISCORD_WEBHOOK_URL=...` を書く
  （`.gitignore` 済みなのでコミットされない。テンプレートは `.env.example` を参照）。
- **Claude Code on the web（リモート環境）**：Environmentの環境変数設定に `DISCORD_WEBHOOK_URL` を
  登録してもらう（Ruuが画面から設定。エージェント側からは設定できない）。
- コミット前に `git status` / `git diff` で `.env` やWebhook URLの文字列が紛れ込んでいないか必ず確認する。

## やらないこと

- 文字起こしにない内容を足さない・話を作らない。
- プロジェクトの新規作成やフォルダ構成の変更を、確認なしに行わない。
- Webhook URLをコード・ノート・コミットメッセージのどこにも書かない。
